## Cross-cutting current-job constraints

1. **Current repo evidence is CLI/module/test-first, not a shipped web app.** `output/findings/ui_surface_map.md:12-17` says the README and parser expose a CLI-oriented `kurort_engine` surface; `ui_surface_map.md:55-57` says no web/UI/API layer was found and idea artifacts must use proof labels rather than over-claiming existing frontend behavior.
2. **Idea artifacts must be proposals, not production implementation.** `plan.md:5` scopes the job as exploration/proposal research, and `plan.md:56-63` excludes production UI/backend implementation plus kiosk, portal, mobile wallet app, broad command center, broad compliance cockpit, guest messaging, and backend-engine proposals.
3. **Deliverable D6 requires 3-4 substantive current-job UI idea artifacts.** `plan.md:30-31` leaves D6/D7 remaining, and `plan.md:183-221` selects the three primary artifacts for Phase 5.
4. **Required artifact sections.** `plan.md:189-204` requires title, summary, target role/workflow, UI design, evidence, project locations, impact, effort, risks/dependencies, validation plan, duplication check, open questions, and evidence labels.
5. **Allowed proof labels.** `ui_surface_map.md:77` and `plan.md:152-156` require labels such as `module-backed`, `CLI-backed`, `test-contract-backed`, `preview-only`, `dry-run`, `stub-shaped`, `negative evidence`, and `requires new API contract`.
6. **No unsupported persistence/auth/permissions.** `ui_surface_map.md:69-70` flags missing persistence and missing role/permission model, so all role names in artifacts are design personas rather than verified authorization boundaries.
7. **No housekeeping/DATEV/POS claims.** `ui_surface_map.md:43-44` and `ui_surface_map.md:71-72` record negative evidence for housekeeping/room-status backend and production DATEV/GoBD/Kasse/TSE/POS screens.

## Duplicate constraints to carry into every artifact

- Avoid a broad **generic reception command center**; Phase 1 says that direction has high duplicate/supersession risk and only a narrow Today shift queue/artifact strip survives (`phase1_duplicate_risk_inventory.md:18`, `:32-33`).
- Do not draft kiosk, self-check-in, guest portal, guest-facing PWA, or new mobile wallet app ideas (`phase1_duplicate_risk_inventory.md:19-21`, `:32`).
- Do not draft broad guest messaging or locale-aware pre-check-in ideas; only staff-only locale/status primitives are safe (`phase1_duplicate_risk_inventory.md:21`, `:34`).
- Do not draft a broad compliance cockpit or full DSGVO Art. 17 cascade; only narrow confirmation modals, retention/exception badges, and evidence drawers are safe (`phase1_duplicate_risk_inventory.md:22`, `:35`).
- Do not draft new backend engines for Meldeschein, Kurtaxe, Kurkarte, spa/wellness, or channel management; visualization/status/exception/handoff layers are the allowed scope (`phase1_duplicate_risk_inventory.md:36`).
- Safe primitive pool: Today shift queue, guest artifact strip, statutory delivery lane, validity timeline, folio/compliance badges, and role-based landing pages (`phase1_duplicate_risk_inventory.md:38-45`).
