## 2. Dead ends to avoid in later idea artifacts

1. **Do not draft a kiosk/self-check-in/mobile guest portal idea.** It duplicates `iter31_002` and carries already-known PWA/offline/multilingual/accessibility risks.
2. **Do not draft another broad single-screen reception command center.** That phrase overlaps prior single-screen UX artifacts and shipped receptionist-command work; use narrower labels such as shift queue, artifact strip, exception lane, or timeline.
3. **Do not draft guest messaging, locale-aware pre-check-in, or multilingual Meldeschein as a new feature.** Those are already covered in `iteration7_002` and `loop16_002`; later UI work may only reuse staff-facing locale-status primitives.
4. **Do not draft a broad compliance cockpit.** DSGVO Art. 17 cascade already owns the compliance action surface and has retention/Art. 9/channel reconciliation risks.
5. **Do not draft new backend engines for Meldeschein, Kurtaxe, Kurkarte, spa/wellness, or channel management in this UI design job.** Those areas already have proposal or shipped surfaces; this job should visualize status, exceptions, and handoffs.

## 3. Candidate non-duplicate UI primitive pool

- **Today shift queue:** a compact list of arrivals, departures, statutory submissions, folio blockers, and room-readiness blockers; anchored to shipped CLI workflows rather than a new command center.
- **Guest artifact strip:** one row per reservation showing Meldeschein, Kurkarte Apple pass, Kurkarte Google object, Kurtaxe, remittance, and key validity states; anchored to arrival-bundle evidence at `iter-16` lines 98-105.
- **Statutory delivery lane:** ready/sent/failed/needs-correction states for Meldeschein/Secra/AVS/Optima, with retry visibility but no new adapter proposal.
- **Validity timeline:** Kurkarte activation, room-key validity, checkout/revocation, and mismatch warnings; this wraps prior temporal-binding logic.
- **Folio/compliance badges:** compact badges for Kurtaxe charged, remittance rows present, Badekur/GKV missing fields, retention blockers, and DSGVO audit state; avoid full compliance cockpit.
- **Role-based landing pages:** receptionist daily queue, housekeeping readiness board, manager exception/control dashboard, reporting/export view, and admin/AVV view. This is navigation/visual design, not new backend scope.
